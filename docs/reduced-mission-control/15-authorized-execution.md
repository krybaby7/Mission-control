## P2 implementation contract

`buildChildEnv(context)` constructs a new string dictionary without a parent environment parameter. Discriminated purposes: selected-provider worker/metadata, verification, rendering, controller Git and diagnostic. Required controller-owned inputs: native absolute PATH entries, intended HOME and TMPDIR; optional narrowly validated locale/timezone. Selected config home maps only to CLAUDE_CONFIG_DIR or CODEX_HOME. Git control inputs are individually typed and produce fixed protected settings, never an arbitrary GIT dictionary. No generic proxy/certificate route is introduced.

Path validation is lexical and rejects Windows/UNC/mounted-drive contamination, relative/traversal/control characters and empty PATH elements. It does not claim symlink or filesystem isolation. Error text names the setting without repeating its value. Unknown secrets, API/billing variables, SSH/Git credentials, shell/Node/loader injection and arbitrary language paths are never selected.

Later adapters derive PATH from native Node's directory plus trusted native tool directories, never inherited PATH. Workers use their owned temporary work directory for HOME/TMPDIR, plus only the selected explicit provider config location. Metadata has its own controlled temporary directories. Verification/browser have no provider config. Controller Git receives explicitly constructed control values. Existing prompt stdin, output parsing, timeouts, descendant cleanup and bypass guards stay in place. Actual provider compatibility remains untried.

Focused fake-child tests and existing caller tests establish behavior; no provider CLI or isolation experiment is used. Rewiring fake scripts must pass their scenario through explicit fixture files/options, not add a production escape for FAKE_* variables.

### Shared lifecycle constraints

Reservation must surround each actual executor runner invocation, including retries. A dispatcher-owned callback closes over the authoritative in-memory Mission; the executor must not load/save a competing copy. Before launch, one mission save records the unique job ID, count and pending writing intent. Before retry or thrown return, save the observation. Metadata and skipped helpers never reserve.

Observed invocation records and accepted append-only WorkEvidence are separate. Appending incomplete and completed WorkEvidence with the same job ID would make the current reader reject it as ambiguous. Acceptance appends one final entry per invocation; retained snapshots identify only contributions that remain after a successful reset/restore or adoption. Failed calls are not assumed write-free. Test authorship is member-grounded.

Accepted state and clearing pending intent are a single save. If saving fails, restore the in-memory pending state so a later error-handler save cannot erase uncertainty. Recovery saves uncertainty before clearing scratch interruption state; it is idempotent by durable identity. Legacy scratch-only recovery needs a stable reconciliation key. Existing pending owner approval is untouched.

Feature review uses premerge passingCommit. Whole-application review uses the verified integration SHA captured before review; any later mutation invalidates both review and resolution credit. Findings retain audit history, but only explicit usable current-head assessments with actual identity and passing current verification can close blocking concerns. Whole-app independence requires complete scaffold and retained feature contribution coverage; unknown must remain unknown.

This section states constraints, not a completed lifecycle schema or an implementation claim. The exact contract and source review are required before its coding stage.
